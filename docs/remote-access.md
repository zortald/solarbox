# Remote access («Доступ») — design

Goal: the owner opens Solarbox from anywhere on the internet when the site has
a public IP, with a login that is safe for changing settings from outside.
No external services, no Let's Encrypt, no extra passwords to remember.

## Transport

- **HTTPS with a self-signed certificate**, generated by Solarbox on first
  start (key + cert in `/data/tls/`, valid 10 years, never reissued). The
  fingerprint never changes, so a browser accepts it once per device.
- **One port.** The server sniffs the first byte of every connection on `:8080`:
  TLS handshake → HTTPS, anything else → plain HTTP. Plain HTTP serves only
  `/api/ingest` (ESP boards cannot do TLS) and `/healthz`; everything else is
  redirected to `https://` on the same host and port. No new NAT rule is needed
  on the LAN side.
- **Fingerprint check.** The certificate's SHA-256 fingerprint is shown on the
  «Доступ» page and sent to Telegram with «доступ открыт». On a new device the
  owner compares it with what the browser shows before accepting. Deploy
  scripts pin the public key (`curl --pinnedpubkey`, `SB_PIN` in
  `deploy/local.env`).
- PWA install and Web Serial still need a trusted certificate; out of scope.

## Login

- **Router login and password.** Solarbox checks them against the router's REST
  API (`GET /rest/system/identity` with Basic auth on the container's default
  gateway, override `SOLARBOX_ROUTER`) and never stores them. Anyone who can log
  in to the router gets full rights in Solarbox.
- **Emergency password** for when the router's REST is unreachable or Solarbox
  does not run on a router: `SOLARBOX_ADMIN_PASSWORD`, or generated on first
  start into `/data/admin-password` and printed once to the container log.
  Login with an empty user name. Deploy scripts use it (`SB_ADMIN`, header
  `X-Admin`, HTTPS only).
- **Sessions:** random token in a cookie (`HttpOnly; Secure; SameSite=Strict`),
  30 days since last use, stored hashed in `/data/sessions.json` so a restart
  does not log anyone out. «Выйти везде» drops all sessions.
- **Brute force:** per client IP, after 5 failed logins a growing pause
  (doubling, capped at 15 min).
- **Daily check:** sessions of router users that no longer exist or are
  disabled on the router are dropped. If the router does not answer, nothing
  is dropped.
- Everything except `/api/ingest`, `/healthz` and the login page needs a
  session. No second factor.

## Firewall

The default MikroTik input chain drops everything not from the LAN list and
the container's bridge is not in it, so the install adds one rule: the
container may reach the router's REST port, nothing else (see
`deploy/routeros.md`). Solarbox cannot add it itself — it needs REST to do
so. When REST is unreachable, the login page says so and «Доступ» shows the
exact command to paste.

## Service user on the router

On the first successful router login Solarbox creates a router user `solarbox`
(group `solarbox-read`: `read,api,rest-api` — REST logs in through the API internally — no `sensitive`, allowed only from the container's address) with a random password
kept in `/data/router.json`. It cannot change anything and cannot see secrets.
Used for: the daily session check, the public IP (every 5 min), the access
status (NAT rule present, public vs CGNAT address). Not removed when access is
closed.

## Opening and closing access (page «Доступ»)

All changes on the router are confirmed with the logged-in user's router
password, which is used once and forgotten.

- **Open:** enable `/ip/cloud ddns-enabled=yes`, pick a random external port in
  20000–60000, add `/ip/firewall/nat` `chain=dstnat dst-address-type=local
  protocol=tcp dst-port=<port> action=dst-nat to-addresses=<container ip>
  to-ports=8080 comment=solarbox-access`. The default MikroTik firewall already
  accepts dst-nat'ed traffic. `dst-address-type=local` (not
  `in-interface-list=WAN`) so the public address and DDNS name work from the
  site's own Wi-Fi too; no hairpin masquerade is needed because the container
  is on its own subnet, not the LAN.
- **Close:** remove the rule(s) with that comment. DDNS and the certificate stay.
- **No public IP** (WAN address in 10/8, 172.16/12, 192.168/16, 100.64/10):
  the page says forwarding is impossible and points to Back To Home.
- **REST unreachable:** the page shows the RouterOS commands to paste and
  checks the result afterwards.
- Entry: `https://<public ip>:<port>`; if the IP changes often, the DDNS name
  `https://<serial>.sn.mynetname.net:<port>`.

## Telegram (switchable, on by default: `notify_access`)

- every successful login (user, IP, browser);
- a series of failed logins from one IP;
- access opened / closed (address, fingerprint);
- public IP changed (new address).
